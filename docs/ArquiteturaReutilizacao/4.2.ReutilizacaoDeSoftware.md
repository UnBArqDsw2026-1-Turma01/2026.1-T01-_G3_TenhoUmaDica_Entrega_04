# 4.2 Reutilização de Software

## Introdução

Reutilização de software é a prática de utilizar artefatos já existentes como frameworks, bibliotecas, padrões de projeto e componentes para construir novos sistemas, evitando retrabalho e aumentando a qualidade do produto. Segundo Pressman (2016), a reutilização reduz custos de desenvolvimento, diminui a ocorrência de erros e acelera a entrega, pois partes já validadas são aproveitadas em novos contextos.

No projeto **#TenhoUmaDica**, a reutilização está presente em diferentes níveis: desde o uso de frameworks consolidados no mercado até a aplicação de padrões de projeto GoF que promovem extensibilidade e reuso interno de código.

## Reutilização no Projeto #TenhoUmaDica

### 1. Reutilização de Framework — React (Frontend)

O frontend foi desenvolvido com **React + TypeScript**, um dos frameworks de UI mais adotados no mercado. O React permite criar **componentes reutilizáveis**, ou seja, elementos de interface construídos uma vez e utilizados em múltiplas telas sem duplicação de código.

No projeto, a tela de avaliações (`AvaliacoesPage`) foi construída reutilizando o padrão de estrutura de páginas já adotado pelo grupo, como o layout base, estilização compartilhada via `App.css` e `index.css`, e o roteamento centralizado definido em `App.tsx`.

**Trecho de código — `AvaliacoesPage.tsx`:**

### 2. Reutilização via Padrão GoF Comportamental — Observer

O padrão **Observer** foi aplicado no backend para notificar observadores sempre que um `PostConteudo` ou `Comentario` sofre alterações. Esse padrão é uma solução reutilizável consagrada (GoF, 1994) para o problema de dependência entre objetos sem acoplamento forte.

A implementação foi estendida com o método `salvarTopico()`, presente tanto na classe `Comentario` quanto em `PostConteudo`, demonstrando **reutilização de interface**: ambas as classes implementam a interface `Notificavel`, garantindo que o mesmo contrato possa ser reutilizado em qualquer tipo de conteúdo do sistema.

**Trecho de código — `Comentario.ts` e `PostConteudo.ts`:**

```typescript
// app/back/src/observer/Comentario.ts
// Commit: c43ede4f552cc87bf38fc53d975cd2e7f71df49f

export class Comentario implements Notificavel {
  private topicosSalvos: string[] = [];
  private observadores: Observer[] = [];

  public salvarTopico(): void {
    this.topicosSalvos.push(this.id);
    console.log(`Comentário [${this.id}] salvo como tópico.`);
  }

  public toJSON() {
    return {
      topicosSalvosCount: this.topicosSalvos.length,
      observadoresCount: this.observadores.length,
    };
  }
}
```

```typescript
// app/back/src/observer/PostConteudo.ts
// Commit: c43ede4f552cc87bf38fc53d975cd2e7f71df49f

export class PostConteudo implements Notificavel {
  private topicosSalvos: string[] = [];
  private observadores: Observer[] = [];

  public salvarTopico(): void {
    this.topicosSalvos.push(this.id);
    console.log(`PostConteudo [${this.id}] salvo como tópico.`);
  }
}
```

> 🔗 Link para o código: [Commit c43ede4 — feat: adição do método salvarTopico()](https://github.com/UnBArqDsw2026-1-Turma01/2026.1-T01-_G3_TenhoUmaDica_Entrega_03/commit/c43ede4f552cc87bf38fc53d975cd2e7f71df49f)

A interface `Notificavel` funciona como um **contrato reutilizável**: qualquer nova entidade do sistema que precise de notificação basta implementá-la, sem precisar reescrever a lógica de observação.

### 3. Reutilização via Testes Automatizados — Jest

Os testes escritos em `observer-topic.spec.ts` utilizam o framework **Jest**, reutilizando sua infraestrutura de mocks e asserções para validar o comportamento das classes sem necessidade de um ambiente real.

```typescript
// app/back/src/observer/observer-topic.spec.ts

describe('Observer salvarTopico', () => {
  it('deve registrar um tópico salvo e refletir isso no toJSON', () => {
    const comentario = new Comentario('comentário de teste');
    comentario.salvarTopico();
    expect((comentario.toJSON() as any).topicosSalvosCount).toBe(1);
  });

  it('deve contabilizar múltiplos salvamentos de tópico', () => {
    const post = new PostConteudo('texto do post', 'descrição do post');
    post.salvarTopico();
    post.salvarTopico();
    expect((post.toJSON() as any).topicosSalvosCount).toBe(2);
  });
});
```

## Senso Crítico

A reutilização no projeto foi aplicada de forma consciente e coerente com as necessidades do sistema. O uso do React no frontend evitou a criação de estruturas de UI do zero, aproveitando um ecossistema maduro com documentação ampla e comunidade ativa. No backend, a interface `Notificavel` e o padrão Observer garantem que novos tipos de conteúdo possam ser adicionados ao sistema sem modificar código existente o que é diretamente alinhado ao princípio Open/Closed (SOLID).

Como ponto de melhoria, a cobertura de testes poderia ser ampliada para cobrir mais cenários de notificação do Observer, e os componentes React poderiam ser abstraídos em uma biblioteca interna de design system para maximizar ainda mais o reuso entre telas.
